Created 2026-11-07, when docs/frontend-fix-plan.txt was finished (all items done; 3.11 was
replaced by 6.2 Chaos EQ). This file collects everything still open, from that plan, from

C. INSTRUMENTS (the biggest musical gap) — roadmap Phase 11
------------------------------------------------------------
Every instrument track type (guitars, piano, strings, drums) plays through TestSynth:
backend/instruments/instrumentfactory.cpp maps all of them to it. The folders
backend/instruments/{sfz,piano,drums,strings} are empty; sampler/ has only samplezone.h;
tools/sfzcheck is empty.
BUILD ORDER (the user, 2026-11-07): the shared sampler first (C1, done), then the harmonium
(C7: synthesis, needs no samples or SFZ), then the SFZ loader (C2), drums (C3), the FLAC
decoder (C4) and the piano (C5).
[x] C1  Sampler engine (hand-written): sample zones, key/velocity mapping, round robins, loop
        points, envelopes, release triggers, choke groups (e.g. closed hi-hat stops the open
        one), voice allocation with a fixed voice pool (no allocation on the audio thread).
        Done 2026-11-07: backend/instruments/sampler/ (zonemap, samplervoice, sampler; Sampler
        is a Processor, typeId "sampler", not yet in instrumentfactory). Tests: backendtests
        sampler. Not in yet: sustain pedal (C5), pitch bend, loop_sustain, rt_decay.
[ ] C2  SFZ loader (hand-written parser, off the audio thread) and tools/sfzcheck (loads an
        SFZ file and reports missing samples, unsupported opcodes, overlapping regions).
        Support the opcodes the chosen libraries use first, including the ARIA extensions
        both use (#define, set_hdcc, ...); add more later.
[ ] C3  DRUMS FIRST: Gogodze Phu Vol II (see C9) as the real "Drums" instrument. WAV
        samples, so no decoder is needed yet. Drum keys, hi-hat choke, mic mix controls.
        Map the Drums track type to it in instrumentfactory.cpp. Sampler::setZones() must not
        run during process(): loading a kit into a live track needs a safe handoff. Listen
        with the user; if it disappoints, switch to the fallback SM Drums (we write its map).
[ ] C4  FLAC decoder, hand-written, in the app (backend, shared): the sampler loads the
        Splendid piano with it, and audio import (E) reuses it later. Stream and frame
        parsing, subframes (constant, verbatim, fixed and LPC prediction), Rice-coded
        residuals, stereo decorrelation, 16/24-bit, MD5 check. Tests: decode reference
        files and compare sample for sample with the same audio as WAV.
[ ] C5  PIANO NEXT: Splendid Grand Piano (see C9) as the real "Piano" instrument, loaded
        through the FLAC decoder. Sustain pedal, release, string resonance controls. Map the
        Piano track type. Listen with the user; if it disappoints, switch to the fallback
        Accurate-Salamander (WAV; CC-BY, so a credit is then required: see C8).
[ ] C6  Other instruments after that: strings, acoustic guitar, bass (samples or the string
        model), mapped in instrumentfactory.cpp.
[x] C7  Harmonium, built 2026-11-07 (before C2, the user's choice); tuning by ear is left (B9).
        Tuning step 1 done 2026-11-08: the Indian reed is a free-reed air-puff model (lopsided
        Hann pulse, derivative radiated; puff width 0.30 at full air, 0.55 at low air), fitted
        to single notes of the references; the old flat overtone stack was the buzz.
        TUNING STEP 2: calm the roughness. 2a done 2026-11-08 (the user liked it): per-key
        detune scatter +-1.5 -> +-0.5 cent (reedvoice.cpp; start phases unchanged). 2b done
        2026-11-08: drones get 55 % of the bellows air (Harmonium::DroneAir), ~6 dB softer and
        darker than a played key. 2c done 2026-11-08: the case reflections go through a 2 kHz
        high-cut and sit a little lower (0.28 at full Case); bright ones combed the 1-3 kHz band
        and sounded hollow. Tuning step 2 is finished.
        SUSTAIN, added 2026-11-08 (the user's idea): a released key keeps ringing, full level for
        half of Settings::sustainSeconds, then fades to silence over sustainSeconds; the next key
        cuts the tail (20 ms). A key let go while a newer key (>80 ms newer) is held ends at once
        (legato), so a chord let go note by note still sustains. Default 1.5 s on new tracks
        (the user's choice); files saved before it load with 0 (plain release). Slider "Sustain"
        on the Harmonium page (0 = Off, up to 4 s). Waiting for the user's test in the app.
        backend/instruments/harmonium/: reedwave (band-limited reed tables, soft/full air),
        reedvoice (one key, all ranks, stops fade on held keys), harmonium (Processor: bellows
        with pumping and reservoir sag, pressure -> level/brightness/flatness, breathy attack,
        air noise, key click, case EQ + short reflections, drones, scale changer, CC 11/2),
        harmoniumsettings; persistence/harmoniumjson. Two styles: Indian (bass/male/female
        reeds, drones) and Western reed organ (Bourdon 16', Diapason 8', Dulciana 8',
        Principal 4', Vox Humana tremolo). Track type "Harmonium" (instrumentfactory maps
        it), settings saved per track, edits reach the engine without a playback rebuild.
        UI: the Harmonium page in the track's FX panel (fixed, like GuitarSuite; each instrument
        names its page in InstrumentDefinition::page). Tests: backendtests
        harmonium, harmoniumjson; wrappertests qtharmonium; transport_ui harmonium_lives_in_fx_*.
        Worst case (32 keys + 4 drones, all ranks) ~2 % of one core.
