[x] 1.10 Pre-existing failing UI tests (all failed at f059241, before this plan started).

[x] 1.11 Leftover test-order problems from 1.10. All fixed:
         - APP bug: every QtQuick.Dialogs dialog (track colour, project open/save, EQ and

           that hidden window kept the app's focus, so nothing in the main window could
           take keyboard focus (typing, renaming and shortcuts stopped working). The 8
           dialogs now use popupType: Popup.Item (inside the main window). Regression
           check added to the colour-picker test, which runs in its normal place again.
         - TEST bug: undo_redo_buttons_restore_deleted_clips clicked 1x1 hidden hooks;
           now uses File > Undo / Redo.
         - TEST bug: presets_qtcheck.cpp:52 armed the track and expected a clean-monitor
           update, but monitoring follows the monitor button (record arm is separate);
           it now enables monitoring.
         - TEST bug: mixer_split_meters_... set "levels" with setProperty(), which keeps
           the binding to EngineController.trackLevels, so live levels overwrote it when
           run alone; now written with QQmlProperty::write.
         Full suites after Phase 1: backend 237/237, wrapper 53 tests 0 failed checks,
         UI 92/92 (at f059241 the UI run had 20+ failures and did not finish).


PHASE 2 — Move logic out of QML (architecture rule 6)
-----------------------------------------------------
[x] 2.1  Piano roll snap/grid math, position formatting and note colours
         (PianoRollView.qml:63-169) → backend + PianoRollWrapper.
         Done: new backend PianoRollGrid (backend/midi/pianorollgrid.h/.cpp) owns division,
         triplet/dotted style, snap on/off, snap floor/delta, new-note and minimum note
         length, quantize step, grid line spacing and the menu option lists; the meter
         comes from the project. PianoRollWrapper exposes it; the QML only calls it.
         Position formatting moved earlier (1.2). Note colours stay in QML (presentation).
[x] 2.1b Use one grid model for the timeline and the piano roll (the timeline keeps its
         own snap modes in backend Timeline today).
         Done: shared backend MusicalGrid (backend/transport/musicalgrid.h/.cpp): meter +
         step, snap nearest/floor/ceil restarting at each bar, drag-delta snap, line
         spacing, on-grid checks. Used by Timeline::snap/isBarLine, PianoRollGrid and
         PianoRollPattern::quantize. Each editor keeps its own menu (timeline: Bars/Beats/
         fractions of a beat; piano roll: note values + triplet/dotted). No behaviour change.
[x] 2.1c Timeline grid-line drawing (Timeline.qml beatGridStride/visibleBeatCount maths)
         still lives in QML; move it to MusicalGrid::lineSpacing. This changes how lines
         thin out when zooming, so check it visually.
         Done without a visual change: the timeline's own stride/first/count rules moved
         as-is into MusicalGrid (lineStride, firstVisibleLine, visibleLineCount) via
         TimelineWrapper. The piano roll ruler ticks, grid-line count/positions and the
         velocity lane ticks also moved (MusicalGrid tickCount, tickLabel, lineCount,
         linePosition, ...). No grid maths is left in Timeline/PianoRoll/VelocityLane QML.
[x] 2.2  Note names / black-key detection (PianoKeys.qml:18-28) → backend/midi.
         Done: backend notenames (backend/midi/notenames.h/.cpp): name ("C4"), black keys,
         C rows, "C4 60" readout, empty for invalid notes. Used via PianoRollWrapper by the
         keys, row shading, note labels and the cursor readout.
[ ] 2.3  Transport time formatting (PlaybackControls.qml:96-102) → backend/core/valueformat.
[ ] 2.4  Mixer target-clip selection (MixerPanel.qml:280-293) → MixerPanelWrapper

[ ] 2.5  GuitarSuiteEditor.qml: tuner string list (use standardtuning.h), beat divisions
