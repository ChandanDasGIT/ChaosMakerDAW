         spacing, on-grid checks. Used by Timeline::snap/isBarLine, PianoRollGrid and
         PianoRollPattern::quantize. Each editor keeps its own menu (timeline: Bars/Beats/
         fractions of a beat; piano roll: note values + triplet/dotted). No behaviour change.

         as-is into MusicalGrid (lineStride, firstVisibleLine, visibleLineCount) via
         TimelineWrapper. The piano roll ruler ticks, grid-line count/positions and the
         velocity lane ticks also moved (MusicalGrid tickCount, tickLabel, lineCount,
         linePosition, ...). No grid maths is left in Timeline/PianoRoll/VelocityLane QML.
[x] 2.2  Note names / black-key detection (PianoKeys.qml:18-28) → backend/midi.
         Done: backend notenames (backend/midi/notenames.h/.cpp): name ("C4"), black keys,
         C rows, "C4 60" readout, empty for invalid notes. Used via PianoRollWrapper by the

         Done: the clock uses the existing backend PlaybackControls::formatTime via

         Done: backend mixer::chooseTargetClip (selected clip on the track, else its first

[x] 2.5  GuitarSuiteEditor.qml: tuner string list (use standardtuning.h), beat divisions
         (use tempodivision.h), pedalType string checks, unit formatting → wrapper

         Done: the owner is EngineController (it applies the setting at startup and when
         saving the session). The menu reads/writes only it; AppSettingsWrapper no longer
         keeps a copy. Also fixed: AppSettingsWrapper rewrote ALL its keys on any change,
         so e.g. changing the piano roll display could reset "restore session" to a stale
         value; each setter now saves only its own key.
[x] 2.7  Make track deletion undoable (Project history only covers clip edits today).
         Done: Project history can hold a "track removed" step (full track copy + row);
         removing a track no longer clears the undo history. Undo restores the track with
         the same id, row, clips, colour and EQ; redo removes it again. TrackListWrapper
         announces just that row (no model reset). EngineController keeps a removed
         track's pedalboard (session data) and gives it back on undo; cleared on new/open.
         The delete confirmation is kept and now says Ctrl+Z brings the track back.

PHASE 6 — User requests (added 2026-11-07, heavy, so done last)
-------------------------------------------------------------------
[ ] 6.1  FX per track type, chosen by the user. Today the FX panel always lists the
         10-band EQ (built into every track: Track::eqGainDb, always run by the engine)
         plus GuitarSuite when supported. Wanted: a guitar track (electric or acoustic)
         opens with GuitarSuite, and the user picks which other FX to add.
         Needs: a per-track effect list (add / remove / reorder, saved in the project and
         session, undo?), the engine chain built from it, an "Add FX" picker in the panel
         (backend rules decide what each track type starts with and what it may add).
         Old projects: keep the EQ on a track when its bands are not flat.
         Decided by the user (2026-11-07):
         - No track starts with an FX chain, except an instrument track, which starts with
           its own instrument FX: Electric/Acoustic Guitar -> GuitarSuite. Piano, Strings
           and Drums have no instrument FX yet, so they start empty (the instrument catalog
           can name one later). Vocal tracks start empty. The 10-band EQ is no longer
           built in; it is an effect the user adds.
         - GuitarSuite is fixed on guitar tracks (cannot be removed) and cannot be added to
           other track types.
         - The user reorders effects freely; the chain runs top to bottom.
         - No undo for FX add / remove / reorder; changes apply immediately.
         - Old projects: no migration (user 2026-11-07: they were only tests).
         Steps:
         [x] 1 Backend model: Track::effects (ordered TrackEffectSlot list) and the rules in
               backend/plugins/effectchain (initial FX per track type, EQ addable once,
               GuitarSuite fixed and never added); Project add/remove/move, no undo.
         [x] 2 Engine: build each track's processing chain from the list (EQ runs only when
               on the chain). TrackInput is trim only (always first); the EQ is its own
               TenBandEq per track (monitor + playback). Vocal/Audio/other tracks no longer
               run a GuitarSuite chain. Until step 3, saved projects load without their EQ.
         [x] 3 Save/load the list in project and session files ("effects": types in chain
               order). User 2026-11-07: old projects were only tests, so no migration; files
               without the list load each type's defaults. Bad lists are rejected; a guitar
               missing GuitarSuite gets it back in front. Pedalboards (and the input trim
               inside them) load only onto tracks with GuitarSuite; others are dropped.
         [ ] 4 Wrapper: expose the list and add/remove/move to QML.
         [ ] 5 FX panel: show the chain, "Add FX" picker, remove (not GuitarSuite), drag to
               reorder.
[ ] 6.2  A professional parametric EQ plugin in the spirit of FabFilter Pro-Q 3 (our own
         design and name, not a copy of its look or branding). Interactive curve with
         draggable band nodes, many band shapes (bell, shelves, cuts with slopes, notch,
         band pass, tilt), per-band solo/bypass, live spectrum analyzer (hand-written FFT,
         see the from-scratch rule). Replaces 3.11.
         Ask first: band count; which extras matter (dynamic EQ, mid/side, linear phase,
         auto-gain, spectrum match); whether it replaces the 10-band EQ or sits beside it.
[ ] 6.3  Improve the guitar suite's sound quality (user request 2026-11-07).
         Ask first: which pedals / amp / cabinet sound weakest, and what "better" means
         (less harsh/fizzy distortion, more realistic amp, aliasing, cab IRs, noise).

[x] 6.4  Setting: stop playback at the end of the arrangement, on or off (user request
         2026-11-07).
         Done: Settings menu > "Stop playback at the end" (default on), owned by
         EngineController like "Restore session on startup", saved as playback/stopAtEnd
         (AppSettings::KeyStopPlaybackAtEnd) and sent to the engine (SetStopAtEnd). The
         setting alone decides (user): on = playback and metronome stop at the end (one
         second after the last clip that can ring on); off = run until Stop/Pause. This
         replaces the "keep playing while the metronome is on" rule from 727442f.
[x] 6.5  Time readout: show hundredths, not milliseconds (user request 2026-11-07).
         Done: both formatters print HH:MM:SS.cc, floored (never rounded up) with a tiny
         tolerance so exact hundredths such as 0.29 s show as .29. The transport clock is
         the only readout using them (valueformat::position has no app caller yet).
         HH:MM:SS.mmm becomes HH:MM:SS.cc (2 digits after the dot), e.g. "00:00:01.25".
         Formatters: backend/core/valueformat.cpp (elapsed time) and
         backend/engine/playbackcontrols.cpp:244; check every readout using them
         (transport bar, status strip, etc.) and their tests.
