This is the architecture of ChaosMaker

The three layers: frontend/ (QML) talks to wrapper/ (Qt C++), and wrapper/ talks to backend/ (plain C++).
Left out: build*/ (generated) and .claude/ (private notes, ignored by git). Empty folders hold a .gitkeep until their phase.

ChaosMaker/
├── backend/                                // pure C++20 engine, no Qt: built as its own static library, dawengine
│   ├── audiofile/                          // worker-side cabinet WAV decoding and resampling
│   │   └── impulsewav.h/.cpp               // bounded RIFF PCM/float loader; mono/stereo, up to 200 ms
│   ├── audiodevice/                        // the sound card
│   │   └── audiodevice.h                   // AudioDevice and AudioCallback, which hide JACK from the engine
│   ├── core/                               // basic types
│   │   ├── audiodata.h                     // decoded audio that never changes
│   │   ├── audioview.h                     // audio someone else owns
│   │   ├── version.cpp                     // its implementation
│   │   └── version.h                       // the engine's version
│   ├── engine/                             // the audio callback
│   │   ├── audioengine.h                   // AudioEngine: the top of the backend
│   │   ├── enginecommands.h                // EngineCommand and EngineEvent, across the thread line
│   │   └── enginesnapshot.h                // the flat read-only song the audio thread plays
│   ├── dsp/                                // shared real-time DSP building blocks
│   │   ├── tempodivision.h                 // shared quarter-note BPM to modulation-rate conversion
│   │   ├── dcblocker.h                     // reusable prepared DC removal for gain pedals
│   │   ├── delayline.h                     // preallocated fractional ring buffer
│   │   ├── peakmeter.h                     // atomic peak accumulation and latched near-full-scale clipping
│   │   ├── pedalcontrols.h                 // shared pedal gain, smoothing coefficients, stereo detection
│   │   ├── oversampler4x.h                 // cascaded filtered 2x stages for amp clipping
│   │   ├── radix2fft.h                     // reusable fixed-size FFT; tables prepared off audio thread
│   │   ├── pitchvoice.h/.cpp                // 1024-point spectral pitch voice, 128-sample hop
│   │   ├── partitionedconvolver.h/.cpp      // direct head + FFT tail; zero added cabinet delay
│   │   └── oversampler2x.h                 // filtered 2x nonlinear processing
│   ├── instruments/sampler/                // the sample engine
│   │   └── samplezone.h                    // one sample and when it plays

│   ├── plugins/chordplayer/                // the auto chord player

Phase 2 verification: tests/plugins/phase2_test.cpp checks gating, compression, wah response, modulation, pitch accuracy, analysis routing, block independence, and finite output.

Tempo: EngineController.bpm is authoritative. TempoEditor commits through TransportBar in Main.qml; the timeline reads EngineController.bpm; AudioEngine validates and stores it atomically, then supplies ProcessContext.bpm to each live block. tests/plugins/tremolosync_test.cpp covers timing, tempo handoff, and smooth changes.

Input calibration: GuitarSuiteModel.inputTrimDb (saved in presets) feeds the engine through EngineController. AudioEngine smooths trim before track EQ and the pedal chain; raw-input analysis remains untouched. PeakMeter accumulates raw, pre-pedal, and stereo output peaks without allocations; EngineController polls at 20 Hz for QML. tests/plugins/monitorlevels_test.cpp covers trim, metering, clips, and raw input preservation.

Amp/cab stage: PedalSlot.resourcePath references an external IR. GuitarSuiteModel uses QtConcurrent
and QFutureWatcher to decode/resample/prepare replacements away from the audio thread, then publishes
an EngineSnapshot. Failed loads preserve the current board. Resource-bearing presets prepare as one
candidate chain before committing; paths are relative to the preset folder. App builds link Qt Concurrent.

EQ presets: TrackListModel exposes factory names/apply and versioned .eqpreset save/load using QSaveFile.
All ten frequencies/gains are validated before the selected track is changed. TrackList.qml hosts the
factory selector and custom file dialogs. tests/plugins/{ampcab,impulsewav}_test.cpp cover DSP and WAV
validation; wrappertests (DAW_BUILD_APP builds) covers Qt model persistence and async resource lifecycle.

Pitch pedals share PitchVoice (streaming phase vocoder, 1024-point FFT / 128-sample hop), with
separate channel state and no audio-thread allocation. Wet-path latency is approximately 1024 samples;
dry mixes remain immediate. Settings use the existing registry, slot bypass and preset model.
The pedalboard is nonmodal and closes on Escape or its close button so transport controls remain usable.
Transport UI tests are a separate Qt Test target (when available), isolated from desktop audio servers.

Crunch and Distortion are separate Processor modules sharing Oversampler4x and DCBlocker. They use
smoothed atomic parameter descriptors, the existing live GuitarSuite snapshot path, bypass/reordering,
and .gspreset persistence; recording is not required. tests/plugins/drives_test.cpp covers response,
EQ/tight controls, stereo isolation, sample rates, block independence, output smoothing and the actual
monitor/bypass/disarm path. Qt preset tests cover both pedal types and their saved values.

Additional effects: Parametric EQ, Fuzz and Phaser use the existing registry, monitoring snapshot and
preset model. Tremolo and Phaser share tempo note-division conversion. Their BPM controls share the
pedalboard's modulation UI, while the separate track ten-band EQ remains independent.
Pedal cards snapshot descriptor metadata once and bind live values separately; parameter updates no
longer rebuild dial delegates or invalidate their focus/grab. tests/plugins/extrafx_test.cpp covers the
new effects; Qt tests cover their presets, Phaser sync controls and stable live dial updates.

Factory chains: GuitarSuiteModel.factoryPresetNames/applyFactoryPreset expose exactly Djent/Jazz.
CMake embeds their .gspreset JSON in appChaosMaker, wrappertests and transporttests under
:/GuitarSuitePresets/. Custom and factory data share the existing parser and snapshot publication.
Factory application keeps current trim and reuses the first loaded cabinet processor at the same
sample rate without resetting/reopening its IR; it uses a new slot/bypass state and enables it.
Other chain settings come from the factory data. Normal file presets retain their saved trim/IR
behavior. Targeted factory/picker tests verify these changes without rerunning pedal DSP tests.

Recording/playback and startup-session milestone (2026-11-01):
- backend/recording/takerecorder.h/.cpp: bounded mono SPSC input ring and worker-owned float32
  WAV writer. Worker builds immutable AudioData for immediate playback; loadTakeWav validates
  and decodes this take format on restoration. Stop/overflow/close finalize the file off audio.
- AudioEngine now executes Play/Pause/Stop/Seek/Repeat/Record commands and reports sample-clock
  transport state through atomics. Raw input is copied before monitoring. A second SnapshotSlot
  holds project playback independently of the live GuitarSuite chain. New playback publications
  atomically replace unconsumed ones, with discarded/retired snapshots freed on the UI thread.
- TrackListModel owns take media, compiles clip/gain/mute/solo playback snapshots, and serializes
  the startup document. Restore validates a candidate, preserves missing media references, scales
  timeline samples to the current device rate, and disarms tracks. Current playback is dry;
  per-track insert/EQ DSP routing and recording latency compensation remain future work.
- EngineController connects transport commands, take lifecycle, clip attachment and normal-exit
  finalization. It uses QSettings for the optional restore preference and QSaveFile for one atomic
  last-session.json, embedding GuitarSuite session data with absolute cabinet IR references.
- frontend/window/TopBar.qml: Settings menu with Restore session on startup. Main.qml attaches
  the project and finalizes on close. Timeline.qml and TransportBar.qml read engine position/state.
- Tremolo adds an envelope/attack detector and delayed modulation fade-in for Sustain only.
  Parameter metadata drives its delay/fade/threshold controls and existing preset serialization.
- tests/recording/recording_test.cpp: sample timing, raw capture, WAV roundtrip, clipping boundaries,
  gain/mute/solo/loop, variable blocks, overflow, shutdown and latest-snapshot publication.
- tests/plugins/tremolosustain_test.cpp: attack preservation, sustained modulation, retriggering,
  silence/noise, decaying low notes and block independence.
- tests/wrapper/recording_qtcheck.cpp: injected offline AudioDevice exercises controller Record →
  Stop → clip → Play → session reopen, close during a take and corrupt-session preservation.
  presets_qtcheck.cpp covers media/control roundtrip and missing files; transport_qtcheck.cpp
  covers the actual sustain checkbox, startup setting and unavailable-audio behavior.
